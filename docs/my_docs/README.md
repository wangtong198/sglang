## 五条写作门

展开任何一个 F / B / C / D 之前过这五条。空壳页只写目的和将要覆盖的清单 ID。

1. **场景**。先写清这一条用在什么场景，以及硬件或平台前提。前提记入 [01-体系总览/03-场景与硬件前提总表](01-体系总览/03-场景与硬件前提总表.md)，展开时回填。
2. **正确性 = 本树实现**。论断只来自本仓库这棵树（`297e54fd105e974cdf401e5b4d20253a22c16f90`，标签 `v0.5.23`）。说不准标「待核」。本环境没有多卡或 DeepEP 的实跑记录时，运行时行为标「源码路径推断，未实测」。
3. **详实**。清单上的一条写完：阶段或分叉、符号、和相邻 ID 的关系、清单里已经记下的开放问题。
4. **逻辑 + 图**。用顺序和分叉说明，并配阶段图或调用关系图。
5. **调用栈图不贴大段代码**。图里保留函数名、这一步做什么、它在链路里的角色。不贴大段源码。

## 与上游树的唯一差异

GitHub 的 push protection 把上游一个 32 位字母数字的类名当成 Mistral API key，拒绝推送含有这段连续字符的 commit。运行时名字没有改：类在定义后用 `"Mistral3" + "ForConditionalGeneration"` 写回 `__name__` 和模块全局变量。涉及文件：

- `python/sglang/srt/models/mistral.py`
- `python/sglang/srt/multimodal/processors/llava.py`
- `python/sglang/srt/configs/model_config.py`
- `python/sglang/multimodal_gen/runtime/models/encoders/mistral_3.py`
- `python/sglang/multimodal_gen/runtime/models/registry.py`（识别被拆开的字符串字面量）
- `test/registered/unit/models/test_mistral3_vision_feature.py`

除此之外，源码树与 `297e54fd105e974cdf401e5b4d20253a22c16f90` 一致。清单 C.1 的 M12 记的是这件事。
