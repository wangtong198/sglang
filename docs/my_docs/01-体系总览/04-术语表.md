# 术语表

启动与请求接入正文里固定下来的说法。定义以本树为准，不另造一套。

| 术语 | 角色 | 定义所在 | 清单 ID |
| --- | --- | --- | --- |
| S0–S6、ready、S4 | 启动的粗阶段。S4 的 tokenizer 建在父进程等 pipe 之前 | [00-阶段总览](../02-流程/01-启动/00-阶段总览.md) | F01–F09 |
| `ServerArgs` | 未解析时是 CLI 记录；`resolve_once` 成功后只读 | [02-声明与封口](../02-流程/01-启动/02-声明与封口.md) | F25–F30 |
| `resolving_view` | 原始字段加 `_resolved_overrides` 的只读投影，后写覆盖先写 | 同上 | F28 |
| `declare_resolution` | 解析期间唯一的合法改写，带来源 | 同上 | F29、F190 |
| `resolve_once` | 成功只跑一遍；失败的记录不能重试 | 同上 | F03、F190 |
| TokenizerManager | 默认在主进程分词并把请求送出。Rust 模式不建 | [04-进程拓扑](../02-流程/01-启动/04-进程拓扑.md) | F09、F189 |
| Scheduler | 子进程。建组、加载、划池、挂树，再进事件循环 | 同上 | F04、F98 |
| DetokenizerManager | 另一个子进程，把 token id 变回文本 | 同上 | F100、F189 |
| `num_dp_ranks` | `dp_size * attn_dp_size`。路由面的 DP rank 数 | [05-分布式初始化](../02-流程/01-启动/05-分布式初始化.md) | F97、F192 |
| `dp_size` | 整模副本数 | 同上 | F192 |
| `attn_dp_size` | TP 组内部的 attention 组数，不把 GPU 数乘大 | 同上 | F192、F202 |
| `init_parallel_runtime` | 每个 scheduler 进程一次。草稿 worker 不再调 | 同上 | F105 |
| WORLD | `tp_size * pp_size` 的进程组，scale joiner 再加 offset | 同上 | F106 |
| `load_format` | S2 收成名字，`get_model_loader` 选 loader 类 | [06-模型加载](../02-流程/01-启动/06-模型加载.md) | F85、F122 |
| 草稿类名改写 | `is_draft_model` 时把 `architectures[0]` 换成 NextN / MTP / DSpark | 同上 | F206 |
| `ReqToTokenPool` | 请求槽到 KV 下标 | [07-KV与前缀树](../02-流程/01-启动/07-KV与前缀树.md) | F131 |
| KV 池 | 物理页。目标与草稿各有存储，请求表可以共享 | 同上 | F126、F194 |
| `tree_cache` | 前缀树，在池和图之后挂上。默认实现是 `UnifiedRadixCache` | 同上 | F129、F130 |
| `mem_fraction_static` | （权重 + KV 池）/ 显存。空则由显存启发式声明 | [03-解析流水线](../02-流程/01-启动/03-解析流水线.md) | F62 |
| pipe ready | `status == "ready"`。早于业务 HTTP | [08-ready](../02-流程/01-启动/08-ready.md) | F136–F138 |
| `GET /ready` | tokenizer 未暂停且健康才 200 | 同上 | F139 |
| S7 | HTTP 或 Engine 体变成 `GenerateReqInput` | [00-阶段总览](../02-流程/02-请求接入/00-阶段总览.md) | F10 |
| S8 | 分词并 ZMQ 下发。chat 模板在这之前的协议层 | 同上 | F11 |
| `GenerateReqInput` | 接入侧 dataclass。调度器不读它 | [02-校验与规范化](../02-流程/02-请求接入/02-校验与规范化.md) | F141 |
| `TokenizedGenerateReqInput` | 发出去的 msgspec 请求，带着 `SamplingParams` | [03-分词与模板](../02-流程/02-请求接入/03-分词与模板.md) | F143 |
| `stream` | 入口旗标。HTTP 用它选 SSE 或一次 `__anext__`。yield 规则在响应篇 | [01-协议入口](../02-流程/02-请求接入/01-协议入口.md) | F10 |
| `Req` | scheduler 里的一份请求。构造时带空的 `ReqKvInfo` | [04-下发与入队](../02-流程/02-请求接入/04-下发与入队.md) | F146 |
| `waiting_queue` | 非 PD 时 `_add_request_to_queue` 的终点 | 同上 | F146 |
| `SamplingParams` | 分词时由 dict 定稿。S10 才拿来采样 | [05-批对象与采样参数](../02-流程/02-请求接入/05-批对象与采样参数.md) | F149 |
| `ScheduleBatch` | 一轮已选中的 `Req` 列表。接入时不构造 | 同上 | F147 |
| `ForwardBatch` | 一轮前向的张量，带 `ForwardMode`。接入时不构造 | 同上 | F148 |

阶段名 S9–S11 的导航在 [01-地图](01-地图.md)。那些阶段的正文还不在请求接入目录。
