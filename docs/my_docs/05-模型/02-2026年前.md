# 2026 年前

本页是年代表的前一张。合入年全部 **待核**。本树没有 `CHANGELOG`，git 是浅克隆，不能用 `git log` 看文件第一次出现的提交，工作区 mtime 是检出时间。

头年份只取该文件前 12 行里的四位年份，当作弱信号。`internvl.py` 头里的 `2077` 丢掉。版权年不是合入年。

和 [03-2026起](03-2026起.md) 的分工，两张表的类名并集覆盖本树全部 LLM `EntryClass`（225 个文件、290 个类行、290 个不同类名）：

- 头年份集合只含 2026，或只含 2026 与无效的 2027：归 2026 起。
- 清单 C.3 点名、用户要单独成行的产品也归 2026 起，即使头上没有年份，或头年份更早。包括 DeepSeek V4 / V4.1 / V4-Flash、GLM-5 / 5.1 / 5.2 / 5.3 / 5.3-Flash、Kimi K2.5 / K3 / Linear、Qwen3 / Qwen3.5 / Qwen3-Next / Qwen4-Exp、Hunyuan V4、MiMo V2、MiniMax-M2，以及这些产品的 MTP / NextN / DSpark 类。
- 其余类留在本表。

「无头年份」和「头年份打架」**不是**已经证实的 2026 年前支持名单。它们留在本表，是因为没有被上面两条收走，而本树每个类都要有一行。头年份 ≤2025 同样只是弱信号。

扩散组件、扩散 pipeline、无 `EntryClass` 的模块不按年拆，全表在 [01-注册表](01-注册表.md)。Gemma4 的因果与多模态文件头含 2025，类在本表；扩散、MTP、unified 头只含 2026，在后一页。Kimi-VL 头含 2025，不在 K2.5 / K3 / Linear 的产品名里，留在本表。MiniMax-M3 头含 2023–2024，留在本表；M2 按产品名去了 2026 起。`Glm4MoeForCausalLM` 与 `GlmMoeDsaForCausalLM` 写在同一个 `glm4_moe.py`：前者留在本表的打架组，后者是 GLM-5.x，在后一页。
